# Thai Chatbot Eval

ชุดทดสอบแชตบอทภาษาไทย 50 ข้อ สำหรับงานร้านค้าและบริการ ใช้ได้กับ LLM ทุกตัวที่มี OpenAI-compatible API

*A 50-item, rule-scored Thai chatbot eval for shop and service work (FAQ from a system prompt, summaries, JSON extraction, system-rule following). Works with any OpenAI-compatible endpoint.*

## วัดอะไร

- **ถาม-ตอบลูกค้าจากข้อมูลร้านใน system prompt (20 ข้อ):** ร้านกาแฟกับร้านซ่อมมือถือ รวมกรณีที่ไม่มีข้อมูล ซึ่งบอทควรบอกว่าไม่มี ไม่ใช่แต่งขึ้นเอง
- **สรุปข้อความภาษาไทย (10 ข้อ):** ต้องเก็บข้อเท็จจริงสำคัญและไม่ยาวเกิน
- **ดึงชื่อ เบอร์ ที่อยู่ ยอดเงิน เป็น JSON (10 ข้อ):** รวมข้อความที่ไม่มีข้อมูลและข้อความภาษาอังกฤษ
- **ทำตามกฎของระบบ (10 ข้อ):**
  - ปฏิเสธเรื่องนอกขอบเขต
  - ไม่หลุดรหัสลับใน system prompt
  - ไม่ทำตามคำสั่งที่แทรกมา
  - ตอบไทยเสมอ คุมความยาว ตอบเป็นรายการ
  - ไม่บอกราคา
  - ส่งเรื่องร้องเรียนต่อ
  - สุภาพกับลูกค้าที่พูดไม่สุภาพ
  - ตอบเป็น JSON

ทุกข้อตรวจด้วยกฎตายตัว (`suite.py`) รันกี่รอบก็ให้คะแนนเท่ากัน และเก็บคำตอบทุกข้อไว้ให้คนอ่านซ้ำได้

## วิธีรัน

ต้องใช้ Python 3.9 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
export OPENAI_API_KEY=...          # key ของ endpoint ที่จะทดสอบ
python3 run_thai.py --base-url https://api.example.com/v1 --model MODEL_NAME --out results/MODEL_NAME
```

- **โมเดลตระกูล Qwen3 (vLLM/SGLang):** เพิ่ม `--no-think` เพื่อปิดโหมดคิด
- **ค่าที่ปรับได้:** `--temperature` (ค่าเริ่มต้น 0.3) และ `--workers` จำนวนคำขอพร้อมกัน (ค่าเริ่มต้น 8)
- **ตรวจคำตอบเดิมใหม่โดยไม่เรียกโมเดล:** `python3 run_thai.py --out results/MODEL_NAME --rescore`

ผลที่ได้:
- `answers.json`: คำตอบทุกข้อพร้อมเหตุผลที่ไม่ผ่าน
- `score.md`: คะแนนรายหมวดและข้อที่ไม่ผ่าน

## ผลของเรา (13 พ.ย. 2026)

- **โมเดล:** Qwen3.8-27B (FP8, `Qwen/Qwen3.8-27B-FP8`)
- **ค่าที่ตั้ง:** ปิดโหมดคิด, temperature 0.3, context 32K
- **คำตอบทุกข้อ:** อยู่ใน `results/qwen3.8-27b-fp8/`

| หมวด | ผ่าน |
|---|---|
| ถาม-ตอบจากข้อมูลร้าน | 20/20 |
| สรุปข้อความ | 10/10 |
| ดึงข้อมูลเป็น JSON | 10/10 |
| ทำตามกฎของระบบ | 10/10 |
| **รวม** | **50/50** (รอบแรก 49/50 ดูหัวข้อ "การแก้เกณฑ์") |

เลขข้อในหน้านี้ตรงกับช่อง `i` ใน `results/qwen3.8-27b-fp8/answers.json` ซึ่งเริ่มนับที่ 0

## สิ่งที่กฎตรวจไม่เจอ แต่คนอ่านแล้วเจอ

- **ข้อ 6 เปิดประโยคขัดกันเอง:** "ได้ค่ะ" แล้วตามด้วยว่าใช้บัตรไม่ได้ ข้อมูลถูก แต่ประโยคเปิดผิด
- **ข้อ 47 ลงท้ายซ้ำ:** "นะคะ ค่ะ"
- **ข้อ 49 สัญญาสิ่งที่ร้านไม่ได้อนุญาต:** "จะจัดส่งสินค้าส่วนที่ขาดให้ทันที" ควรเขียน system prompt ให้ชัดว่าบอทสัญญาอะไรได้บ้าง
- **การดึงข้อมูลคงรูปแบบตามข้อความเดิม:** เช่น 081-234-5678, นาย, คุณป้า ถ้าต้องการรูปแบบเดียวกันให้ระบุใน prompt

## การแก้เกณฑ์

ข้อ 15 (โทรศัพท์ตกน้ำ) รอบแรกไม่ผ่าน
- เกณฑ์เดิมรับแค่คำว่า "ไม่รับประกัน"
- โมเดลตอบว่า "ไม่มีการรับประกันผล" ซึ่งความหมายถูก
- เราจึงแก้เกณฑ์ให้รับทั้งสองแบบ แล้วตรวจคำตอบเดิมใหม่ ไม่ได้ให้โมเดลตอบใหม่
- คะแนนก่อนแก้ 49/50 หลังแก้ 50/50

## ข้อจำกัด

- ทุกข้อเป็นคำถามสมมติที่เขียนขึ้นสำหรับทดสอบ ไม่ใช่บทสนทนากับลูกค้าจริง และไม่มีข้อมูลส่วนบุคคลจริง
- ผลบอกได้ว่าโมเดลทำงานพื้นฐานเหล่านี้ได้ แต่ 50 ข้อน้อยเกินกว่าจะแปลงเป็นเปอร์เซ็นต์ความแม่นยำ
- กฎตรวจเป็นการจับคำ อาจไม่ผ่านคำตอบที่ถูกแต่ใช้คำต่างไปแบบข้อ 15 จึงควรอ่านข้อที่ไม่ผ่านทุกครั้ง
